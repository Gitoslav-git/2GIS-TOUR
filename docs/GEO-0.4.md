# GEO и защита внешнего API в версии 0.4

## Географические уточнения

`INTENT` возвращает `locationHint`: часть города, район либо ориентир, явно названный пользователем. Частые формулировки центра и сторон города дополнительно распознаются детерминированно, поэтому ошибка LLM не должна потерять «в центре», «на севере», «на юге», «на востоке», «на западе» и составные направления.

- Без уточнения поиск выполняется вокруг центра выбранного города с радиусом 12 км.
- «Центр» использует центр города из Places API и радиус 3,5 км.
- Сторона города использует смещение 4,5 км от полученного в 2ГИС центра и радиус 4,5 км.
- Именованный район или ориентир разрешается отдельным поиском 2ГИС; принимается только точка не дальше 25 км от центра Тулы или Владимира, затем применяется радиус 3 км.
- Если именованное уточнение не разрешено, API возвращает `GEO_CONSTRAINT_NOT_FOUND`, а не игнорирует его.

Успешный `Route.searchArea` содержит показанную пользователю подпись, координату центра поиска, радиус и источник `city|direction|2gis`. Сами места, их координаты и все публикуемые пешие участки по-прежнему получаются только из 2ГИС.

## Снижение нагрузки

Backend применяет четыре независимые меры:

1. Одинаковый запрос одной гостевой сессии к `POST /v1/routes` кэшируется на 600 секунд даже при новом `X-Request-Id`.
2. Ответы Places кэшируются на 900 секунд, Routing — на 1800 секунд. Повторный участок получает новые `fromOrder`/`toOrder`, но те же проверенные данные пути.
3. В один момент времени к 2ГИС отправляется не больше двух вызовов. В 0.4.1 общий запрос использует до трёх кэшируемых поисков типов мест, один поиск еды и до десяти проверок участков; подбор прекращается раньше после заполнения 90% времени.
4. Для временных сетевых ошибок допускается максимум один повтор с задержкой. Ответ `429` от 2ГИС не повторяется: `Retry-After` сразу открывает общий предохранитель, а новые запросы получают `DGIS_RATE_LIMITED` HTTP 503 и не обращаются к 2ГИС до его закрытия. Реальные внешние вызовы дополнительно распределяются с настраиваемым минимальным интервалом.

Параметры TTL и числа повторов перечислены в `.env.example`. Кэши текущего этапа находятся в памяти одного процесса и очищаются при перезапуске backend; постоянный распределённый кэш потребуется перед горизонтальным масштабированием.

Версия 0.4.2 использует `GET /3.0/items/byid` для пакетной проверки окончательного списка ручного редактирования. До восьми уникальных `placeId` отправляются одним запросом в стабильном отсортированном виде, чтобы перестановка того же набора использовала кэш; затем ответ восстанавливается в порядке пользователя. Точка отклоняется, если 2ГИС не вернул её, запретил маршрутизацию или данные указывают на другой город; при отсутствии городских атрибутов для пилота применяется проверка расстояния не более 25 км от центра выбранного города.

## Пересчёт текста

`GET /v1/routes/{routeId}` возвращает текущую доступную владельцу версию. `POST /v1/routes/{routeId}/revisions` принимает `baseVersion`, `mode=CHANGE_QUERY`, новый `query` и необязательные `filters`. Backend полностью повторяет INTENT, GEO, расписание и бюджет. Только после успеха тот же `routeId` атомарно получает `routeVersion + 1`. Ошибка внешнего сервиса, геоуточнения или бюджета не изменяет сохранённый маршрут. Устаревшая версия получает `VERSION_CONFLICT` HTTP 409.
