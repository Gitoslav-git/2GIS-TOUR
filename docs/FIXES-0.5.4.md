# Проверка версии 0.5.4

## Выбор старта

Backend выбирает исходную точку строго в таком порядке:

| Геопозиция | Старт указан в тексте | Фактический старт |
| --- | --- | --- |
| Есть | Нет | Координаты пользователя |
| Нет | Есть | Найденный в 2ГИС ориентир |
| Нет | Нет | Центр выбранного города |
| Есть | Есть | Найденный в 2ГИС ориентир |

Ориентир из текста всегда приоритетнее геопозиции. Направление вроде «в сторону центра» не подменяет старт. В ответе API сохраняются `startLat`, `startLon` и `startSource`; Android показывает источник старта без вывода координат.

## Редактирование и сброс

- После успешного применения изменений редактор точек закрывается. При конфликте версии он остаётся открыт и показывает актуальный маршрут для повторной правки.
- Перестановка отправляет полный новый порядок. Backend повторно получает реальные места по `placeId`, строит каждый пеший участок от сохранённого старта и заново вычисляет суммарное и свободное время.
- Кнопка **«Сбросить маршрут»** появляется только после построения. После подтверждения `DELETE /v1/routes/{routeId}` удаляет маршрут и его версии на backend, очищает связанный кэш и локальный запрос Android. Выбранный город и доступ к геопозиции не сбрасываются.

## Сценарий проверки

1. С геопозицией построить запрос без начальной точки: в результате должно быть «Старт: геопозиция пользователя».
2. В том же состоянии написать «от МЦК Кутузовская в сторону центра»: стартом должен стать ориентир из текста.
3. Без геопозиции указать начальную точку: стартом должен стать найденный ориентир.
4. Без геопозиции и без ориентира выбрать город: маршрут должен начаться от центра города.
5. Поменять местами две точки и применить: редактор закроется, версия увеличится, переходы и время пересчитаются.
6. Нажать **«Сбросить маршрут»** и подтвердить: запрос, точки и кнопки текущего маршрута исчезнут; можно построить новый.
