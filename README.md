# Гуляй — Android Java и backend

Версия `0.4.1` — исправляющий этап разработки полного MVP `1.0`. Главный источник требований — `docs/source/2ГИС Системная аналитика.docx`; решения и открытые вопросы записаны в `docs/DECISIONS.md`, границы выпусков — в `docs/RELEASES.md`. Для прибытия к точке принято N = 75 м.

## Что исправлено в 0.4.1

Маршруты больше не хранятся только в оперативной памяти. Backend записывает текущий маршрут, исходный запрос, владельца и `routeVersion` в SQLite `backend/data/gulyay.sqlite3`, поэтому `GET /v1/routes/{id}` и изменение текста работают после перезапуска backend. Android дополнительно сохраняет текущий `routeId` и версию локально. Если приложение держит старый маршрут от версии 0.4, которого ещё нет в новой базе, первое изменение автоматически построит новый маршрут вместо ошибки `NOT_FOUND`.

Запрошенное время теперь является не только верхней границей, но и целью заполнения. Для запроса без конкретной темы GEO получает разные типы реальных мест: достопримечательности, парки/скверы и памятники. ROUTE проверяет до десяти кандидатов и прекращает подбор около 90% бюджета. Ответ и Android отдельно показывают `requestedMinutes`, `totalMinutes` и `unusedMinutes`. Если подходящих открытых мест всё равно недостаточно, остаток объясняется предупреждением; время посещения не растягивается искусственно.

## Что проверять в 0.4.1

Приложение позволяет выбрать Тулу или Владимир, написать пожелания и нажать **«Построить маршрут»**. Backend разбирает запрос через LLM, ищет настоящие места через Places API 2ГИС и получает подробный пеший путь до каждой включённой точки через Routing API 2ГИС. Android показывает порядок точек, длительность посещений, расстояние и время переходов, доступность по расписанию и предупреждения.

Географическое уточнение теперь не ограничено центром: поддерживаются стороны города («на севере», «в юго-западной части»), именованные районы и ориентиры («в Заречье», «рядом с Кремлём»). Для сторон города точка поиска рассчитывается относительно реального центра города из 2ГИС; район или ориентир сначала разрешается через Places API. Разрешённая область явно показана в результате. Если уточнение нельзя надёжно найти в выбранном городе, маршрут не строится молча и возвращается `GEO_CONSTRAINT_NOT_FOUND`.

Повтор того же запроса одной сессии в течение 10 минут возвращает сохранённый результат. Places кэшируется на 15 минут, пешие участки — на 30 минут. Одновременно выполняется не больше двух внешних вызовов; при `429` соблюдается `Retry-After`, выполняются не более двух повторов и включается временная блокировка новых вызовов. Число поисков интересов и проверяемых Routing-кандидатов ограничено. Значения можно изменить переменными из `.env.example`, но увеличивать их при ограниченном тарифе 2ГИС не рекомендуется.

После успешного построения можно изменить текст и нажать **«Изменить маршрут»**. Используется нормативный `POST /v1/routes/{id}/revisions`: успешный пересчёт сохраняет тот же `routeId`, увеличивает `routeVersion`, а при ошибке старый маршрут остаётся на экране и в backend. Порядок кандидатов сокращает лишние переходы эвристикой ближайшего соседа, но все показанные расстояния, времена и геометрия по-прежнему поступают только из Routing API.

Встроенной карты, прохождения, ручного редактирования отдельных точек и партнёрских предложений пока нет. Редактирование точек вынесено в `0.4.2`. Время посещения — явно показанная временная оценка 40/60 минут, потому что оно не поступает из 2ГИС; правило вынесено в `VISIT-01`.

## Backend на компьютере с эмулятором

Нужны Python 3.12+, Android Studio / SDK 35, JDK 17 и Gradle 8.13. Из корня проекта установите backend и запустите тесты:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e './backend[test]'
pytest backend/tests -q
```

На Windows PowerShell используйте `py -3 -m venv .venv`, `.\.venv\Scripts\Activate.ps1`, `pip install -e ".\backend[test]"` и `python -m pytest backend/tests -q`. Установленный у заказчика Python 3.13 подходит.

Для живого маршрута укажите в терминале backend четыре значения. Один ключ 2ГИС можно поставить в обе переменные только если для него подключены оба продукта:

```powershell
$env:OPENAI_API_KEY="<ключ OpenAI API>"
$env:OPENAI_MODEL="gpt-4o-mini"
$env:DGIS_PLACES_API_KEY="<ключ Places API 2ГИС>"
$env:DGIS_ROUTING_API_KEY="<ключ Routing API 2ГИС>"
.\.venv\Scripts\python.exe -m uvicorn gulyay.api:app --host 127.0.0.1 --port 8000
```

Проверьте в браузере компьютера `http://127.0.0.1:8000/health`: ответ должен содержать версию `0.4.1`. Окно PowerShell нужно оставить открытым во время проверки. Ключи не вставляйте в приложение, репозиторий или скриншоты; они хранятся только в окружении backend.

## APK для Android Emulator

Из корня проекта соберите отладочную сборку с адресом **запущенного на этом компьютере** backend. В bash:

```bash
DEBUG_BACKEND_BASE_URL=http://10.0.2.2:8000 gradle :app:assembleDebug
```

В PowerShell: `$env:DEBUG_BACKEND_BASE_URL="http://10.0.2.2:8000"; gradle :app:assembleDebug`. Установите `app/build/outputs/apk/debug/app-debug.apk` на эмулятор. В APK по умолчанию остаётся `https://example.invalid`: такая сборка может показать интерфейс, но не сможет построить маршрут. Специальный адрес `10.0.2.2` доступен только из Android Emulator на том же компьютере. Для backend на внешнем сервере вместо локального адреса задайте `BACKEND_BASE_URL=https://<ваш-домен>` при сборке; опубликованный сервер должен работать по HTTPS. Локальный HTTP разрешён только для `10.0.2.2` в отладочной сборке.

На GitHub Actions workflow **Verify and build APK** проверяет backend и собирает установочный APK в разделе **Artifacts** запуска. Чтобы скачать APK, который работает с локальным backend на вашем эмуляторе, задайте в репозитории *Settings → Secrets and variables → Actions → Variables* значение `DEBUG_BACKEND_BASE_URL=http://10.0.2.2:8000`, затем запустите workflow. Для внешнего HTTPS-сервера используйте переменную `BACKEND_BASE_URL`. Секрет `DGIS_SDK_KEY_BASE64` понадобится при подключении мобильной карты 2ГИС; значения всех переменных указаны в `.env.example`. После успешной проверки этапа можно пометить исходники тегом `v0.4.1`; артефакт Action хранится 30 дней и при необходимости сборку можно запустить снова.

Правила интеграции описаны в `docs/GEO-0.4.md`, а сохранение и заполнение времени — в `docs/STORAGE-0.4.1.md`. `/v1/routes/interpret` сохранён для отдельной проверки разбора, а нормативный `POST /v1/routes` строит маршрут только из ответов 2ГИС.
