# Нерешённые вопросы перед выпуском 1.0

Нормативный документ: «2ГИС Системная аналитика.docx», разделы 1–9. `SRC` описывает исходные схемы, `DEC` — предложенное техническое решение, `TBD` — ожидаемое решение владельца продукта. Приложенный в этом запросе текст фиксирует полную версию 1.0 по бизнес-требованиям и отменяет прежний сокращённый состав MVP.

| ID | Требуется утвердить | Последствие до ответа |
| --- | --- | --- |
| BIZ-01 | Полный исходный комплект скриншотов бизнес-требований либо текстовая копия: в рабочей поставке сейчас есть только аналитика. | Нельзя подтвердить полноту 1.0 и разрешить конфликты между `SRC`, `DEC` и бизнес-требованиями. |
| GEO-01 | Значение `N` в метрах; нужны ли два замера, точность 50 м и интервал 5 с из `DEC-08`? | Автоматическое достижение нельзя считать принятым; `75 м` в аналитике — предложение, а не утверждённое N. |
| PARTNER-01 | Откуда берётся список партнёров, какие идентификаторы 2ГИС и города в нём есть, кто отвечает за актуальность? | Не показывать вымышленные партнёрские карточки. |
| PARTNER-02 | Правило выбора: в какой момент, на каком расстоянии от пути, по каким категориям/времени работы, сколько показов, нужна ли оплата или согласие? | Не выдавать случайное предложение и не менять активный маршрут. |
| SDK-01 | Право на использование продуктов 2ГИС: доступы для Places API, Routing API и файл `dgissdk.key` для Android Map SDK. Проверить поддерживаемую версию SDK и методы/лимиты в тарифе. | Невозможно проверить реальную карту и пути на устройстве. Бесплатный демо-ключ не работает с мобильным SDK согласно официальной документации 2ГИС. |
| INFRA-01 | URL вашего GitHub-репозитория или подключение GitHub для создания репозитория; HTTPS-адрес развёрнутого backend. | Проект может быть подготовлен локально, но не опубликован в вашем GitHub и не подключён к рабочему серверу. |
| AUTH-01 | Поставщик доставки SMS/почты, условия согласия и контракт обновления access token: `DEC-03` требует refresh, но в перечне API-01–19 нет метода refresh. | Нельзя завершить вход, профиль и историю без безопасного способа доставки/продления сессии. |
| GEO-02 | Поведение ручного адреса старта: раннее описание MVP допускает его, `DEC-06` из аналитики предусматривает GPS либо приблизительный центр города. | Определить по исходным бизнес-требованиям; не считать центр точной геопозицией пользователя. |
| WALK-01 | Подтвердить `DEC-09`: автозавершение, пауза, отличие крестика от стопа. | Нельзя проверить контрольные сценарии прохождения как окончательные бизнес-правила. |
| DATA-01 | Сроки хранения истории и гостевых маршрутов, согласие и связь гостевой прогулки с учётной записью. | `24 часа` в аналитике — проектное предложение, а не утверждённая политика. |

Приоритет при противоречии: явное текущее поручение → приложенные бизнес-требования → подтверждённые `SRC` → принятые `DEC`. Неподтверждённые `DEC` и `TBD` не заменяют решение заказчика.
