# Гуляй — Android Java и backend

Версия Android и backend `0.6.9.l` — корректирующий выпуск этапа `0.6` на пути к полному MVP `1.0`. Главный источник требований — `docs/source/2ГИС Системная аналитика.docx`; решения и открытые вопросы записаны в `docs/DECISIONS.md`, границы выпусков — в `docs/RELEASES.md`.

## Что изменено в 0.6.9.l

Город из приложения теперь является источником истины: без принятой геопозиции используется город, выбранный в списке, а с принятой геопозицией — город, автоматически определённый приложением. Отсутствие названия города в запросе, фразы «центр города» и ошибочно заполненный LLM `cityText` больше не вызывают конфликт. Ошибка остаётся только при явном другом городе в тексте, включая неподдерживаемый город.

После ручного выбора города экран явно сообщает, какой город выбран и что без геопозиции маршрут начнётся от его центра. Пример со скриншота «хочу прогуляться по центру города 5 часов» при выбранной Москве обрабатывается как прогулка по центру Москвы.

## Что изменено в backend 0.6.9.k

Routing-проверки разделяются между вариантами маршрута: общий направленный переход проверяется один раз, его геометрия и время повторно используются с корректными номерами точек. Недоступные переходы также запоминаются на время построения. Лимит `ROUTE_MAX_ROUTING_CHECKS` остаётся равным 8 по умолчанию; проверенные переходы доступны после исчерпания лимита.

Рядом с лучшим предварительным вариантом выбирается наиболее высоко оценённый альтернативный вариант, чьи уникальные переходы помещаются в общий лимит. Для него резервируются проверки. Первый успешный результат больше не завершает сравнение: выбирается лучший из проверенных вариантов, с приоритетом выполнения пожеланий. Если два полных варианта в лимит не помещаются, сохраняется возможность проверить один длинный маршрут, включая явный запрос восьми точек. Глобально оптимальный маршрут при ограниченном бюджете не гарантируется.

`searchArea`, предупреждение об области и финальный debug-лог теперь соответствуют выбранному варианту. Если расширенный поиск не улучшил результат, сохраняется исходная область. Жёсткое ограничение района не ослабляется.

Обновление применяется поверх `0.6.9.j`. Достаточно перезапустить backend; установленный APK `0.6.9.j` совместим, изменения API-контракта отсутствуют. `/health` должен показывать `0.6.9.k`.

Проверки: 116 тестов backend прошли, 4 интеграционных пропущены без настроенных внешних сервисов. Четыре регрессионные проверки воспроизводят ошибки на исходной `0.6.9.j` и проходят после исправления. Живые вызовы 2ГИС и проверка APK этим запуском не выполнялись.

## Что изменено в 0.6.9.j

Построитель больше не публикует первый допустимый маршрут. Он группирует расширенный набор кандидатов 2ГИС в компактные кластеры, формирует несколько вариантов, предварительно оценивает их без лишних Routing-вызовов и проверяет лучшие варианты по реальным пешим участкам. Итоговая оценка учитывает длительность, интересы, число и разнообразие точек, ходьбу, компактность, район и еду. Плохой вариант запускает следующую попытку; ослабляются только мягкие предпочтения, а жёсткие ограничения повторно проверяются перед публикацией.

`TARGET` и `MAXIMUM` теперь влияют на качество по-разному: целевой маршрут должен заполнить не менее 85% времени, а максимальная длительность остаётся потолком и не требует искусственного заполнения. Обычная прогулка не публикуется с одной точкой; исключение — явный запрос одного места. Темп и плотность реально меняют число точек, конкретная кухня и время еды сохраняются как ограничения.

Добавлен сквозной структурированный лог `gulyay.planning`: запрос → сырой результат LLM → нормализованные HARD/SOFT-ограничения → кандидаты 2ГИС → варианты и их оценки → причина окончательного выбора либо явная ошибка. Невалидный ответ LLM по-прежнему завершает запрос ошибкой и не включает скрытый fallback.

## Что изменено в 0.6.9.i

LLM теперь возвращает нормализованное намерение, а не набор строк для 2ГИС. Отдельно хранятся режим длительности (`TARGET`, `MAXIMUM`, `APPROXIMATE`), старт, область, нормализованные интересы, исключения, еда, темп и мобильность. Исходный текст и неизвестные значения не передаются в каталог: backend преобразует допустимые концепты в собственный проверенный набор запросов 2ГИС.

Мягкое пожелание «не хочу много ходить» больше не становится жёстким лимитом. Оно повышает компактность и задаёт желаемый переход около 20 минут, но backend может постепенно расширить кластер ради полноценной прогулки. Жёсткий предел применяется только при явном численном требовании вроде «между точками максимум 15 минут» или «не больше километра».

Построитель проверяет заполнение целевой длительности: хороший маршрут использует не менее 85% времени. Слишком короткий маршрут возвращается с `planningStatus=DEGRADED`, коэффициентом `durationUtilization` и перечнем невыполненных пожеланий, а не маскируется под полноценный результат. Время посещения оценивается по типу места и выбранному темпу; поиск расширяется безопасными backend-запросами без дополнительного вызова LLM.

## Что изменено в 0.6.9.h

После оценки роли LLM модель по умолчанию скорректирована с избыточной `gpt-6-astra` на `gpt-5.4-mini`. Это более подходящий баланс для единственного короткого вызова со строгой схемой: выше уровень, чем у прежней `gpt-4o-mini`, но без лишней стоимости и задержки флагманской модели.

## Что изменено в 0.6.9.g

Модель семантического разбора повышена с `gpt-4o-mini` до `gpt-6-astra`. Она используется через прежний `Responses API` и прежний строгий `IntentExtraction`, поэтому LLM по-прежнему только извлекает параметры и не создаёт места или маршруты. `gpt-6-astra` теперь является безопасным значением по умолчанию, но его можно заменить переменной `OPENAI_MODEL` без изменения кода.

Таймаут единственного LLM-вызова увеличен с 8 до 20 секунд, чтобы более сильная модель не давала ложную ошибку на первом запросе со схемой. `/health` показывает поле `llmModel`, по которому можно проверить реально выбранную модель.

## Что исправлено в 0.6.9.f

Естественные управляющие фразы больше не передаются в 2ГИС как поисковые интересы. Пожелания `недалеко ходить`, `короткие переходы`, `между точками не больше 15 минут` преобразуются в числовое ограничение времени одного пешего перехода. Ограничения в метрах и километрах переводятся в минуты с расчётной скоростью 80 м/мин.

Защита работает на двух уровнях: результат LLM очищается при формировании `QueryPreview`, а непосредственно перед `2GIS Places` применяется повторный фильтр. Неизвестные управляющие условия отбрасываются; если после очистки интересов не осталось, используются безопасные базовые запросы `достопримечательности` и `парки и скверы`.

## Что исправлено в 0.6.9.e

Телефон и Android Emulator используют единый внешний backend `https://deviator-coaster-venture.ngrok-free.dev`. Локальные адреса `10.0.2.2` и `192.168.0.123` больше не участвуют в текущей сборке. В Gradle и GitHub Actions осталась одна переменная `BACKEND_BASE_URL`, поэтому адрес можно заменить без изменения Java-кода.

Во все запросы добавлен заголовок `ngrok-skip-browser-warning: true`, чтобы ngrok возвращал JSON backend, а не HTML-страницу предупреждения. Существующее логирование `GulyayNetwork` продолжает показывать фактический URL, endpoint, статус и тип ошибки.

## Что исправлено в 0.6.9.d

Одна debug-сборка теперь работает в обеих тестовых средах. На Android Emulator она автоматически выбирает `http://10.0.2.2:8000`, а на физическом Android — `http://192.168.0.123:8000`. Старый `DEBUG_BACKEND_BASE_URL` больше не используется и не может случайно направить физический телефон на адрес эмулятора. В дальнейшем адреса меняются централизованно через `EMULATOR_BACKEND_BASE_URL`, `DEVICE_BACKEND_BASE_URL` и production-переменную `BACKEND_BASE_URL`.

Вся работа с адресом вынесена в `BackendConfig`: там определяются среда, итоговый URL, нормализация и проверка схемы. `ApiClient` больше не обращается к `BuildConfig` напрямую. В Logcat с тегом `GulyayNetwork` записываются выбранный URL, HTTP-метод, endpoint, статус ответа, время запроса и точный тип сетевого исключения. Незашифрованный HTTP явно разрешён только для debug APK; основной manifest и release-конфигурация сохраняют запрет и требуют HTTPS.

## Что исправлено в 0.6.9.c

Debug APK больше не ограничен адресом Android Emulator `10.0.2.2`: при сборке можно передать локальный адрес компьютера, например `http://192.168.1.50:8000`, и тестировать приложение на физическом телефоне в той же сети Wi‑Fi. Разрешение незашифрованного HTTP действует только в debug-сборке; release по-прежнему принимает только HTTPS.

Если соединение не установлено, приложение показывает адрес backend, фактически зашитый в APK, и пишет техническую причину в Logcat с тегом `GulyayNetwork`. Это позволяет отличить неверную сборочную переменную от недоступного сервера.

## Что исправлено в 0.6.9.b

Точки маршрута на карте приведены к use case: каждая точка отображается зелёным пином с номером и видимым названием места. Подпись рисуется вместе с bitmap-маркером, поэтому её показ не зависит от автоматического размещения текста Map SDK. Старт от рабочей геопозиции обозначается синей точкой пользователя; при старте без гео остаётся отдельный подписанный маркер начала маршрута.

Во время активной прогулки вместо общей плашки показывается отдельная карточка манёвра: расстояние до ближайшего поворота, направление, следующая точка и расчётное время пешком. Подсказка и значок поворота пересчитываются локально по полученной от Routing геометрии и системной позиции, без дополнительных запросов к 2ГИС.

## Что исправлено в 0.6.9.a

После аварийного закрытия отдельного процесса карты главный экран больше не считает маршрут потерянным: при сохранённом `routeId` всегда доступна кнопка **«Вернуться к маршруту»**. Перед открытием приложение запрашивает активную прогулку у backend и восстанавливает тот же `walkId`, следующую точку и оставшееся время. Это не зависит от ненадёжного обмена `SharedPreferences` между Android-процессами.

При состоянии **«Локация не определена»** тускло-красным становится всё поле выбора города, а стрелка остаётся обычной. После ручного выбора доступного города поле возвращается к штатному светлому виду.

На карте добавлена отдельная оранжевая метка старта, включая старт от центра города или текстового ориентира без геопозиции. Все места маршрута получают заметные зелёные нумерованные метки, созданные как bitmap для стабильной отрисовки Android Map SDK. После запуска прогулки белая плашка показывает направление по реальной геометрии Routing: движение прямо, ближайший левый/правый поворот и расстояние до него. Подсказка пересчитывается локально по очередному системному GPS-измерению и не расходует квоту запросов 2ГИС.

## Что исправлено в 0.6.9

Карта 2ГИС вынесена в отдельный Android-процесс `:map`: нативный SDK больше не делит heap с главным экраном, а сбой карты не должен завершать основной процесс приложения. SDK и `MapView` инициализируются лениво только после успешной загрузки маршрута, что убирает пик памяти от одновременного разбора JSON и запуска карты. При критическом давлении на память остаётся рабочий экран точек с понятной заглушкой вместо вылета.

Ограничение камеры перенесено с `OnTouchListener` внутреннего `MapView` на `dispatchTouchEvent` экрана, поэтому оно срабатывает и при жестах, которые перехватывает SDK. Минимальный масштаб равен масштабу всего маршрута; после инерции камера повторно проверяется и возвращается в границы.

Геометрия ограничена 120 реальными точками на переход и 360 точками на весь Android-маршрут. Ограничение применяется также к старым маршрутам из SQLite. Для диагностики в Logcat добавлен тег `GulyayMapMemory` с Java heap, native heap и доступной памятью на каждом этапе запуска карты.

Если карта снова закроется на тестовом устройстве, снимите точную диагностику:

```powershell
adb logcat -c
adb logcat GulyayMapMemory:I AndroidRuntime:E libc:F DEBUG:F '*:S'
```

## Что исправлено в 0.6.8

В строке выбора города появилась явная стрелка. Если геопозиция и город не определены, красной становится только стрелка; после ручного выбора она возвращается к обычному цвету.

Для тестов добавлен Боровск Калужской области: выбор на Android, LLM-проверка города, поиск Places, Routing и центр карты используют единый `cityId=borovsk`.

Карта ограничена областью маршрута с небольшим запасом, а минимальный масштаб не даёт уйти далеко от точек. Жесты масштабирования сохранены; справа добавлены кнопки `+` и `−`. Геометрия по-прежнему берётся из Routing API 2ГИС, но число точек полилинии ограничено на backend и Android, чтобы не переполнять память.

## Что исправлено в 0.6.7

Один запрос построения больше не создаёт неконтролируемый всплеск обращений к 2ГИС. Первичный подбор выполняет максимум два поиска категорий (и один отдельный поиск еды при необходимости), проверяет не более шести кандидатов через Routing API, а реальные внешние вызовы распределяются с минимальным интервалом 0,75 секунды. Ответ `429` от 2ГИС не повторяется: backend сразу включает общий предохранитель на время из `Retry-After`, поэтому повторные нажатия не продлевают блокировку ключа.

Два разных ограничения теперь различимы. Собственный лимит приложения остаётся ответом `429 RATE_LIMITED` и разрешает не более пяти дорогих действий за минуту. Ограничение внешнего API возвращается как `503 DGIS_RATE_LIMITED` с пометкой `dependency: 2gis`; Android показывает точную причину и время ожидания. В консоли backend появляется безопасное предупреждение с доменом сервиса и временем ожидания, без вывода ключа.

Настройки защиты можно менять на backend через `DGIS_MIN_REQUEST_INTERVAL_SECONDS` и `DGIS_MAX_RETRIES`. Повторы сетевых сбоев по умолчанию сокращены до одного; ответы о превышении квоты не повторяются независимо от этой настройки.

## Что исправлено в 0.6.6

Определение геопозиции ограничено двумя фактическими попытками за скользящую минуту. Ограничение сохраняется при пересоздании главного экрана. Исправлен таймаут поиска позиции: раньше он был запланирован через скрытую кнопку, не добавленную в окно, поэтому при отсутствии координат слушатель мог не остановиться через 20 секунд. Теперь используется основной UI-таймер и слушатели гарантированно снимаются.

Во время активной прогулки Android отправляет backend не больше двух координат за минуту и не чаще одного раза в пять секунд. GPS и сетевой провайдер запрашивают обновления не чаще раза в 30 секунд, а при сворачивании экрана отслеживание останавливается. Backend дополнительно отклоняет третью геопозицию в скользящем минутном окне с кодом `429`, поэтому ограничение действует и для старых сборок клиента.

Системное получение координат Android и `POST /v1/walks/{walkId}/positions` сами по себе не обращаются к 2ГИС. Places и Routing вызываются только при построении, изменении маршрута и поиске места. Если лимит именно серверного ключа 2ГИС продолжит расходоваться при полностью бездействующем приложении, нужно проверить использование ключа другими процессами или его утечку.

У кнопок изменения и возврата отключены системная тень и анимация высоты, ряд принудительно обрезает содержимое по своим границам и отделён от сообщения нижним отступом. Кнопки больше не заходят на текстовый блок.

## Что исправлено в 0.6.5

Ряды действий на главной и экране маршрута выровнены: кнопки имеют одинаковую высоту, более аккуратные пропорции и не конфликтуют с системной нижней областью. Экран больше не сжимается и не поднимает нижние вкладки при открытии клавиатуры; клавиатура закрывается нажатием вне поля ввода.

При рабочем Android Map SDK текст заглушки полностью удаляется из слоя карты и больше не перекрывает маршрут. Карта остаётся интерактивной и поддерживает штатное перемещение и масштабирование жестами 2ГИС. Если SDK недоступен, понятная заглушка сохраняется.

Карточка маршрута теперь показывает все оставшиеся точки, а не только три. Список прокручивается вертикально внутри отведённой области, при этом заголовок, сводка и кнопки действий остаются на месте. Это же поведение используется во встроенном редакторе точек.

## Что добавлено в 0.6.4

При переходе с экрана маршрута к изменению текста текущий маршрут и активная прогулка теперь сохраняются. На главной появляются две кнопки: **«Изменить маршрут»** отправляет новый запрос, а **«Вернуться к маршруту»** открывает прежний предпросмотр или ту же активную сессию с уже достигнутыми точками. Старая прогулка останавливается и удаляется из локального активного состояния только после успешного построения изменённого маршрута; при ошибке LLM, 2ГИС или backend пользователь может вернуться к исходной сессии.

Изменять текст теперь можно и во время активной прогулки. Лента быстрых фильтров помещена в отдельную обрезаемую область без теней кнопок, поэтому крайние элементы не рисуются поверх соседних блоков; прокрутка по горизонтали сохранена.

Проверка сценария: запустите прогулку, пройдите хотя бы одну точку, нажмите **«Изменить маршрут»**, затем **«Вернуться к маршруту»** — номер следующей точки и остаток времени должны сохраниться. Повторите, но отправьте новый текст: после успешного пересчёта должен открыться новый предпросмотр; при намеренной ошибке backend должен остаться доступен старый маршрут.

## Что добавлено в 0.6.3

Редактирование точек больше не закрывает экран маршрута. Кнопка **«Редактировать точки»** включает встроенный режим и меняется на **«Подтвердить»**. В нём точку можно удалить крестиком, а порядок изменить перетаскиванием за область `≡`. Кнопка **«Добавить точку»** открывает отдельный полноэкранный поиск по реальным местам 2ГИС; выбранное место добавляется в черновик маршрута.

До подтверждения изменения остаются локальным черновиком. После подтверждения backend атомарно проверяет `placeId`, заново строит переходы и пересчитывает время. При ошибке исходный маршрут сохраняется, при конфликте версии приложение загружает актуальные точки и предлагает повторить правки.

## Что исправлено в 0.6.2

Главная и экран маршрута стали статичными по вертикали: размеры автоматически уплотняются на невысоких устройствах, а основная страница больше не прокручивается. Шесть быстрых фильтров размещены в отдельной горизонтальной ленте и остаются визуальными заглушками. Нижняя навигация содержит только вкладки «Главная» и «Профиль» без рамок.

Экран готового и активного маршрута перестроен по компактному макету: карта занимает верхнюю часть, поверх неё показана сводка, в нижней карточке находятся текущая точка, время, количество мест, сокращённый список и единый ряд действий. При отсутствии ключа 2ГИС тот же макет работает с заглушкой карты.

## Что добавлено в 0.6.1

Главная страница приведена к согласованному макету: верхний городской блок, выбор города, ввод пожеланий, визуальные быстрые фильтры, заглушки истории, профиля и нижних вкладок. Фильтры и разделы-заглушки пока не меняют запрос и не требуют backend.

После построения маршрут автоматически открывается поверх главной страницы. До старта показываются карта или её безопасная заглушка, первая точка, список мест и кнопки изменения. Зелёная кнопка подтверждает начало прогулки и переводит этот же экран в активное состояние. Во время прогулки показываются текущая точка и оставшееся время; красная кнопка и крестик полностью отменяют прогулку и маршрут. Фотографии мест оставлены визуальными заглушками до подключения источника изображений.

## Что добавлено в 0.6

Фразы о коротких переходах теперь являются числовым фильтром. «Недалеко», «места рядом» и похожие пожелания означают максимум 20 минут на один пеший участок; пользователь может задать своё число или диапазон, например 15–20 минут. Эти слова не передаются 2ГИС как название района. Сначала отсеиваются заведомо далёкие кандидаты, затем лимит проверяется по реальному `durationSeconds` Routing API.

После построения доступна кнопка **«Начать прогулку»**. В активном режиме Android передаёт позицию backend; прибытие подтверждается двумя измерениями в радиусе 75 м, с точностью не хуже 50 м и интервалом не менее 5 секунд. После достижения приложение переходит к следующей точке, а остаток обновляется по фактически прошедшему активному времени. Поддержаны пауза, возобновление, остановка и автоматическое завершение на последней точке. Закрытие карты не останавливает прогулку.

Старт маршрута выбирается по четырём явным правилам: без текстового старта используется рабочая геопозиция, при её отсутствии — центр выбранного города; если пользователь написал начальную точку, найденный в 2ГИС ориентир приоритетнее геопозиции. Направление («в сторону центра») и начальная точка («от МЦК Кутузовская») остаются разными параметрами.

После построения появилась кнопка **«Сбросить маршрут»** с подтверждением. Она удаляет текущий маршрут на backend, очищает локальный запрос и позволяет начать заново. После успешного применения изменений редактор точек закрывается. При новом порядке backend заново строит все пешие участки от сохранённого старта и пересчитывает итоговое время; при ошибке старый маршрут остаётся действующим.

После построения маршрута доступна кнопка **«Показать на карте 2ГИС»**. Отдельный экран показывает точки по координатам backend, маршрут — по реальной геометрии его пеших участков Routing API, а при разрешённой геопозиции — старт пользователя. Android не рисует выдуманную прямую линию при отсутствии геометрии.

LLM-разбор различает конкретную стартовую точку (`startLocationHint`), направление движения (`directionHint`), область прогулки (`locationHint`) и пожелание коротких переходов (`preferShortWalks`). Например, запрос «от МЦК Кутузовская в сторону центра» начинает маршрут от найденной в 2ГИС станции, а центр использует как направление, не как старт. Неуникальный ориентир вроде «мой офис на Кутузе» требует уточнения названия или адреса вместо угадывания.

При запуске приложение проверяет последнюю системную позицию и одновременно запрашивает свежую через GPS и сетевой источник. Тула, Владимир, Москва или Боровск выбираются автоматически по координатам. Если определить поддерживаемый город не удалось, список показывает **«Локация не определена»**, после чего пользователь вручную. Ввод координат не требуется. В API-06 уходят координаты и точность измерения; при ручном выборе используется явно обозначенный приблизительный старт. Запрос и текущий маршрут сохраняются при повороте главного экрана.

Если позиция определена или сброшена после расчёта, кнопка предлагает перестроить маршрут от нового старта. При ошибке старый маршрут не удаляется.

Android Map SDK зафиксирован на версии `13.6.0`. Мобильный `dgissdk.key` подставляется локально или через секрет Actions и никогда не коммитится. Если ключ отсутствует или не подходит тарифу, приложение показывает понятную ошибку вместо падения. До решения `CONSENT-01` диагностическая статистика SDK отключена через `PersonalDataCollectionConsent.DENIED`.

## Что проверять в 0.6

1. Постройте маршрут с фразой «желательно, чтобы до локаций идти было недалеко»: результат должен показать мягкое предпочтение около 20 минут, но не жёсткий максимум.
2. Проверьте «между точками максимум 15–20 минут» и «не больше 12 минут пешком»: только в этих случаях должны появиться жёсткие лимиты 20 и 12 минут.
3. Запустите прогулку и выполните сценарий из `docs/WALK-0.6.md`: две геопозиции, переход к следующей точке, пауза, продолжение и стоп.
4. Закройте активную карту кнопкой **«Назад»**: на главном экране должна появиться кнопка **«Продолжить прогулку»**.
5. Достигните последней точки: статус должен стать `COMPLETED`, а активная прогулка — исчезнуть.

Функции предыдущих этапов сохранены: LLM-разбор геоуточнений, реальные Places/Routing, защита от частых запросов, SQLite, изменение текста, ручное редактирование и карта. Партнёрских предложений в 0.6 ещё нет. Правило посещений 40/60 минут остаётся открытым вопросом `VISIT-01`.

## Мобильный ключ 2ГИС

Нужен именно файл мобильного Android Map SDK `dgissdk.key`, выданный 2ГИС для `applicationId` `ru.gulyay.app`. Это не серверные ключи Places/Routing. Для локальной сборки на Windows:

```powershell
New-Item -ItemType Directory -Force ".\app\src\main\assets"
Copy-Item "C:\путь\к\dgissdk.key" ".\app\src\main\assets\dgissdk.key"
```

Для GitHub Actions преобразуйте весь файл в Base64:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\путь\к\dgissdk.key")) | Set-Clipboard
```

Добавьте скопированное значение в *Settings → Secrets and variables → Actions → Secrets → New repository secret* с именем `DGIS_SDK_KEY_BASE64`. Сам файл и Base64 нельзя публиковать в Git или сообщениях.

## Backend на компьютере для эмулятора или телефона

Нужны Python 3.12+, Android Studio / SDK 35, JDK 17 и Gradle 8.13. Из корня проекта установите backend и запустите тесты:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e './backend[test]'
pytest backend/tests -q
```

На Windows PowerShell используйте `py -3 -m venv .venv`, `.\.venv\Scripts\Activate.ps1`, `pip install -e ".\backend[test]"` и `python -m pytest backend/tests -q`. Установленный у заказчика Python 3.13 подходит.

Для живого маршрута укажите в терминале backend четыре значения. Один ключ 2ГИС можно поставить в обе переменные только если для него подключены оба продукта:

```powershell
$env:OPENAI_API_KEY="<ключ OpenAI API>"
$env:OPENAI_MODEL="gpt-5.4-mini"
$env:DGIS_PLACES_API_KEY="<ключ Places API 2ГИС>"
$env:DGIS_ROUTING_API_KEY="<ключ Routing API 2ГИС>"
.\.venv\Scripts\python.exe -m uvicorn gulyay.api:app --host 0.0.0.0 --port 8000
```

Проверьте локально `http://127.0.0.1:8000/health`, а затем через туннель `https://deviator-coaster-venture.ngrok-free.dev/health`: ответ должен содержать версию `0.6.9.l` и выбранную модель в `llmModel`. Окна Uvicorn и ngrok нужно оставить открытыми во время проверки. Ключи не вставляйте в приложение, репозиторий или скриншоты; они хранятся только в окружении backend.

## APK для Android Emulator или физического телефона

Из корня проекта соберите отладочную сборку с внешним HTTPS-адресом backend. В bash:

```bash
BACKEND_BASE_URL=https://deviator-coaster-venture.ngrok-free.dev gradle :app:assembleDebug
```

В PowerShell адрес уже является значением по умолчанию, поэтому достаточно `gradle :app:assembleDebug`. Для другого туннеля перед сборкой задайте `$env:BACKEND_BASE_URL="https://<новый-домен>"`.

Телефон и компьютер могут находиться в разных сетях. Важно, чтобы работали Uvicorn и туннель ngrok. Установите `app/build/outputs/apk/debug/app-debug.apk`: один и тот же APK работает на телефоне и эмуляторе.

На GitHub Actions workflow **Verify and build APK** проверяет backend и собирает установочный APK в разделе **Artifacts** запуска. В *Settings → Secrets and variables → Actions → Variables* оставьте одну переменную `BACKEND_BASE_URL` со значением `https://deviator-coaster-venture.ngrok-free.dev`. Старые `DEBUG_BACKEND_BASE_URL`, `EMULATOR_BACKEND_BASE_URL` и `DEVICE_BACKEND_BASE_URL` удалите. Для карты сохраните секрет `DGIS_SDK_KEY_BASE64`. После изменения переменной обязательно запустите новую сборку и установите новый APK.

Для проверки подключения запустите backend, откройте приложение и нажмите **«Построить маршрут»**. В Uvicorn должна появиться строка `POST /v1/routes`. Одновременно можно смотреть клиентскую диагностику:

```powershell
adb logcat -s GulyayNetwork
```

И на физическом устройстве, и на эмуляторе первая строка должна содержать `url=https://deviator-coaster-venture.ngrok-free.dev`. Затем появятся `HTTP start` и либо `HTTP response`, либо `HTTP failure` с типом ошибки.

Прохождение описано в `docs/WALK-0.6.md`, карта и геопозиция — в `docs/MAP-0.5.md`; предыдущие этапы — в `docs/GEO-0.4.md`, `docs/STORAGE-0.4.1.md` и `docs/EDIT-0.4.2.md`. `/v1/routes/interpret` сохранён для отдельной проверки разбора, а нормативный `POST /v1/routes` строит маршрут только из ответов 2ГИС.
