# Интеграция 2ГИС в версии 0.3

`POST /v1/routes` сначала разбирает запрос через INTENT, затем получает центр выбранного города и реальные объекты через Places API 2ГИС. Для пожелания `centerOnly=true` используется радиус 3500 м от центра, иначе 12000 м. Доступные тестовые города — Тула, Владимир, Москва и Боровск. Результаты без `id`, имени, координат или с `is_routing_available=false` исключаются.

Для каждой рассматриваемой точки backend запрашивает подробный пеший участок `POST /routing/7.0.0/global` с `transport=walking` и `output=detailed`. В `RouteLeg.geometry` попадают только координаты из геометрии ответа Routing API в порядке `[lon, lat]`. Если участок отсутствует, точка исключается; прямая линия между координатами не создаётся.

Расписание проверяется в часовом поясе `Europe/Moscow`, общем для всех текущих тестовых городов, на момент предполагаемого прибытия и до конца посещения. Точка со статусом `CLOSED` исключается. При отсутствии расписания допустим `UNKNOWN` с предупреждением пользователю.

Версия 0.3 сохраняет порядок релевантности Places API и вставляет запрошенную еду после первых достопримечательностей. Оптимизация всей последовательности относится к 0.4. Время посещения не приходит из 2ГИС: до решения `VISIT-01` используются показанные пользователю оценки 40 минут для обычного места и 60 минут для еды.

Нужны `DGIS_PLACES_API_KEY` и `DGIS_ROUTING_API_KEY` в окружении backend. При отсутствии или отказе ключа возвращается `GEO_UNAVAILABLE`; секрет не попадает в ответ. Успешный маршрут содержит 1–8 реальных `placeId`, точки, реальные пешие участки, суммарное время и предупреждения. Повтор с той же парой `X-Device-Session`/`X-Request-Id` возвращает тот же сохранённый маршрут.
