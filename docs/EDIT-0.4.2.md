# Ручное редактирование маршрута в версии 0.4.2

## Пользовательский сценарий

После построения пользователь открывает **«Редактировать точки»**. Android запрашивает актуальный маршрут через `GET /v1/routes/{routeId}` и формирует локальный черновик. В черновике можно удалить точку, переместить её на одну позицию выше или ниже, выполнить поиск и добавить выбранное место. До кнопки **«Применить изменения точек»** backend и текущая версия маршрута не меняются.

Поиск вызывает `GET /v1/places?cityId=…&q=…` с `X-Device-Session`. Ответ содержит не более десяти реальных кандидатов с `placeId`, названием, координатами и признаком еды. Пустой результат отображается как отсутствие подходящих мест, а не заменяется фиктивной точкой.

## Контракт изменения

Android отправляет:

```json
{
  "baseVersion": 2,
  "mode": "EDIT_POINTS",
  "pointIds": ["2gis-id-3", "2gis-id-1", "2gis-id-7"]
}
```

`pointIds` является полным итоговым порядком, содержит от одной до восьми уникальных строк. Backend одним вызовом `GET /3.0/items/byid` повторно получает объекты и восстанавливает порядок из запроса. Затем он проверяет выбранный город, расписание каждой точки, пешеходный путь от старта и между всеми соседними точками, а также общий бюджет времени.

После успешной проверки выполняется атомарное сохранение с условием `routeVersion = baseVersion`; ответ сохраняет `routeId` и увеличивает `routeVersion` на один. Предыдущий снимок остаётся в `route_versions` для будущей привязки истории и прохождения к точной версии. `ROUTE_NOT_FOUND`, `TIME_BUDGET_EXCEEDED`, `GEO_UNAVAILABLE` и `RATE_LIMITED` не меняют сохранённый маршрут. При `VERSION_CONFLICT` клиент загружает актуальную версию и просит пользователя повторить локальные правки.

## Защита лимита 2ГИС

Перемещение, удаление и добавление выполняются внутри Android без сетевого запроса. Полная проверка и пересчёт запускаются один раз после подтверждения. Поиск выполняется только по явному нажатию, результаты Places и Routing используют TTL-кэши и общий предохранитель версии 0.4.

## Проверка на эмуляторе

1. Построить маршрут в Туле или Владимире.
2. Открыть редактор, поменять порядок двух точек и применить; должна появиться следующая версия и новые переходы.
3. Удалить точку и применить; суммарное и свободное время должны измениться.
4. Найти место по названию, добавить его в черновик и применить.
5. Добавить точки сверх бюджета; приложение должно оставить предыдущий маршрут и показать ошибку.
6. Перезапустить backend и снова открыть редактор; актуальная версия должна загрузиться из SQLite.
