# Проверка VISITING UI на Android Emulator

## Подготовка

1. Запустите backend по адресу, с которым собрана APK. Для сборки с внешним `BACKEND_BASE_URL`
   дополнительный `adb reverse` не нужен; для специально собранного локального варианта настройте
   соединение с `tcp:8000` согласно его debug-конфигурации.
2. Установите актуальный `app-debug.apk` на Android Emulator Medium Phone.
3. Откройте маршрут минимум с тремя точками и начните прогулку.
4. В Extended controls → Location задайте координаты первой точки дважды с точностью не хуже
   50 м и интервалом не меньше 5 секунд. С учётом действующего rate limiting иногда потребуется
   дождаться следующего доступного окна отправки позиции.
5. Убедитесь по экрану или Logcat, что backend вернул `phase=VISITING`, а
   `currentPointOrder` не изменился.

## Что проверить в VISITING

- Карта и кнопки масштаба остаются видимыми.
- Поверх карты показана светлая карточка с зелёной галочкой, текстом «Вы на месте», названием
  текущей точки и подписью «Вы в зоне локации».
- В нижней панели последовательно видны: «Точка N из M», название текущего места, нейтральная
  заглушка «Фото», крупная зелёная карточка «На локации» с секундомером и карточка «Далее».
- Секундомер считает вверх. После PAUSE число не меняется; после RESUME продолжает отсчёт.
- После принудительного закрытия и повторного открытия Activity секундомер восстанавливается из
  backend-состояния и не начинается с нуля.
- Заглушка фотографии не нажимается и не вызывает сетевых запросов.
- Между карточкой «Далее» и списком нет пустого рекламного места и текста об отсутствии партнёров.

## Карточка «Далее» и выход

1. Сравните название следующей точки с маршрутом.
2. Сравните расстояние и время с `legs` ответа маршрута: UI не должен вычислять или придумывать
   эти значения. Если метрик нет, показывается только название следующей точки.
3. На последней точке карточка «Далее» должна полностью исчезнуть.
4. Задайте координаты дальше 115 м дважды с требуемым интервалом. После подтверждённого выхода
   промежуточная точка возвращается в MOVING; верхняя карточка снова становится навигационной,
   а зелёный секундомер исчезает.

## Маленький экран и длинное название

1. Повторите проверку на Android Emulator Medium Phone и при высоте экрана не больше 720 dp.
2. Используйте маршрут с длинным названием текущей точки.
3. Название должно занимать не более двух строк и не заходить под блок «Фото».
4. Карта не должна сжиматься в узкую полосу, карточка «Далее» и нижние кнопки должны оставаться
   видимыми. На обычной высоте второстепенный список прокручивается; в compact VISITING до 720 dp
   он скрывается, чтобы не вытеснять управление за пределы экрана.

Фактические эталоны текущей реализации на Medium Phone сохранены в
[`docs/screenshots/visiting-ui-medium-phone.png`](screenshots/visiting-ui-medium-phone.png) и
[`docs/screenshots/visiting-ui-paused-medium-phone.png`](screenshots/visiting-ui-paused-medium-phone.png).

Сделайте снимки в одинаковом размере и масштабе карты:

1. MOVING непосредственно перед прибытием.
2. VISITING на промежуточной точке: верхняя карточка, таймер, «Далее», фото и нижние кнопки.
3. VISITING на паузе.
4. VISITING на последней точке без карточки «Далее».
5. MOVING после подтверждённого GPS-выхода.
6. VISITING с длинным названием на Medium Phone.

Для автоматического снимка можно выполнить:

```powershell
adb shell screencap -p /sdcard/visiting-ui.png
adb pull /sdcard/visiting-ui.png .
```
