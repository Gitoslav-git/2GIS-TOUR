# Путь к MVP 1.0

Каждый этап должен иметь тег `v0.x`, зелёные проверки backend и Android и установочный APK в артефактах GitHub Actions. Версии `0.x` — промежуточные срезы разработки полного 1.0.

| Версия | Проверяемая граница | Статус |
| --- | --- | --- |
| 0.1 | Java Android UI, выбор Тулы/Владимира, ввод запроса, устойчивость ввода к повороту, HTTPS-клиент, каркас backend, контракт ошибок, тесты, CI APK. | Собрана в GitHub Actions и запущена на эмуляторе; backend не был подключён к APK. |
| 0.2 | LLM разбор в структурированные поля, уточнение города/длительности, проверка некорректного ответа, безопасное хранение ключа backend; отладочная связь с локальным backend эмулятора. | Проверена заказчиком на Android Emulator; выявлен и исправлен пропуск пожелания «в центре». |
| 0.3 | Реальные Places и Routing API 2ГИС; проверка часов, длительностей и достижимости; интеграционные проверки Тулы и Владимира. | Проверена заказчиком; высокая частота запросов временно исчерпала лимит 2ГИС и стала входом для 0.4. |
| 0.4 | Геоуточнения района/части/ориентира; кэш, ограниченные повторы и предохранитель для 2ГИС; сокращённый подбор порядка; атомарный пересчёт по новому тексту. | Код и изолированные проверки готовы; живая проверка ожидает восстановления лимита и серверные ключи. |
| 0.4.1 | SQLite-хранение маршрута между перезапусками; восстановление изменения; добор реальных открытых мест к запрошенному времени; явный остаток бюджета. | Реализовано и передано заказчику. |
| 0.4.2 | Ручное добавление, удаление и перестановка отдельных точек через API-09/API-08; пакетная проверка реальных placeId и атомарный пересчёт. | Проверена заказчиком; переход к следующему этапу подтверждён. |
| 0.5 | Встроенная карта 2ГИС, геопозиция, состояние при повороте; маршрут и точки по серверным координатам/геометрии. | Реализовано; ожидает мобильный `dgissdk.key`, сборку GitHub Actions и проверку заказчиком. |
| 0.5.1 | Лимит 5 дорогих операций в минуту; только свежая геопозиция с проверкой выбранного города; строгая фильтрация туристических мест; Москва. | Реализовано по результатам проверки 0.5. |
| 0.5.2 | Автоопределение Тулы, Владимира или Москвы по системной позиции; состояние «Локация не определена» и ручной выбор города; удалена отдельная кнопка работы без гео. | Реализовано по результатам проверки 0.5.1. |
| 0.5.3 | Раздельный LLM-разбор старта, направления, области и коротких переходов; стартовый ориентир проверяется в 2ГИС; неоднозначный личный ориентир требует уточнения. | Реализовано по запросу проверки маршрута от МЦК Кутузовская. |
| 0.5.4 | Четыре явных правила выбора старта; полный сброс маршрута; закрытие редактора после применения; обязательный пересчёт переходов и времени при перестановке точек. | Реализовано по результатам проверки редактора и старта маршрута. |
| 0.6 | Числовой лимит пеших переходов; прохождение, пауза, фактическое активное время, обновление остатка и дедупликация геопозиции; N = 75 м и проверки `DEC-08`. | Реализовано; требуется проверка на реальном устройстве или эмуляторе с управляемой геопозицией. |
| 0.6.1 | Новый интерфейс по трём согласованным макетам: главная, предпросмотр и активный маршрут; полноэкранный переход, запуск и единая отмена через крестик/красную кнопку; заглушки карты, фото, фильтров, истории и профиля. | Реализовано; карта продолжает работать при наличии `dgissdk.key`, без ключа показывается заглушка. |
| 0.6.2 | Статичная адаптивная главная без вертикального скролла; шесть фильтров в горизонтальной ленте; две нижние вкладки без рамок; компактный экран маршрута по детальному UI-референсу. | Реализовано по результатам визуальной проверки 0.6.1. |
| 0.7 | Партнёрские предложения по согласованному источнику и правилу выбора. | Ожидает решения владельца продукта и реализации. |
| 0.8 | Вход по телефону/почте, профиль, история, разрешения и выход в соответствии с аналитикой. | Ожидает провайдера доставки и реализации. |
| 1.0 | Полный сквозной процесс из бизнес-требований и аналитики; реальные интеграционные и инструментальные тесты; исправленные ошибки; выпущенный APK. | Не выпущена. |

Не переименовывать текущий этап в `1.0`. Сборка 0.5 считается полностью интеграционно подтверждённой только после живой проверки Places, `items/byid`, Routing и Android Map SDK для Тулы и Владимира. Эвристика автоматической генерации не объявляется математически оптимальным маршрутом; точная оптимизация остаётся обязательной до 1.0.
