# P4: ручная проверка гостевой истории

## Подготовка

1. Запустите backend с отдельной тестовой SQLite-базой. Не используйте рабочую базу:

   ```powershell
   $env:GULYAY_DB_PATH = "$env:TEMP\gulyay-p4-test.sqlite3"
   $env:GULYAY_ROUTE_RETENTION_MINUTES = "1440"
   python -m uvicorn gulyay.api:app --app-dir backend --host 0.0.0.0 --port 8000
   ```

2. Установите debug APK и убедитесь, что эмулятор подключён к этому backend.
3. Для повторного чистого прогона остановите backend, удалите только созданный
   `gulyay-p4-test.sqlite3`, затем запустите его снова.

## История из трёх маршрутов

1. В приложении последовательно создайте четыре разных маршрута одной гостевой сессии.
2. Откройте раздел «История маршрутов».

Ожидаемый результат: показаны ровно три последних карточки. Каждая содержит город,
название, число мест, длительность и статус. Повторяющихся карточек нет. Под историей
виден текст о лимите трёх маршрутов, 24 часах хранения и будущих профилях; кнопки
регистрации нет.

## Старый маршрут и перезапуск

1. До создания трёх последних маршрутов откройте первый маршрут и остановите прогулку
   через меню прогулки, либо оставьте его готовым к старту.
2. После четвёртого маршрута сверните приложение и завершите процесс приложения через
   Android Studio/adb, затем откройте его снова.

Ожидаемый результат: сохранённый первый маршрут не объявляется удалённым только потому,
что его нет среди трёх карточек. Для `STOPPED` отображается остановленная прогулка, для
`COMPLETED` — пройденный маршрут, а `ACTIVE`/`PAUSED` восстанавливаются через backend.

## Перезапуск backend и отсутствие сети

1. Загрузите историю, затем остановите и снова запустите backend с тем же
   `GULYAY_DB_PATH`.
2. Нажмите на область статуса истории, если отображается сообщение об ошибке.
3. Отключите сеть эмулятора либо остановите backend и ещё раз обновите экран.

Ожидаемый результат: после перезапуска backend история остаётся доступной из SQLite.
При ошибке сети ранее показанные карточки не исчезают, появляется сообщение с повторной
попыткой; после восстановления сети повторная загрузка обновляет список.

## Удаление из истории

1. На готовой, остановленной или завершённой карточке нажмите «Удалить».
2. В диалоге выберите «Отмена».
3. Повторите действие и подтвердите удаление.

Ожидаемый результат: после отмены карточка остаётся. После успешного ответа backend
удаляется только выбранная карточка, остальные не меняются. При отключённом backend или
ошибке сервера карточка остаётся и выводится сообщение об ошибке.

## Защита активной прогулки

1. Запустите прогулку и, при желании, поставьте её на паузу.
2. Откройте историю маршрутов.

Ожидаемый результат: для `ACTIVE` и `PAUSED` удаление не выполняется; приложение просит
сначала завершить или остановить прогулку. Даже если статус карточки устарел, backend
возвращает отказ, а маршрут и прогулка сохраняются.

## Проверка retention

Не изменяйте время и не удаляйте данные рабочей базы. Для автоматизированной проверки
retention используйте отдельную SQLite-базу и backend-тесты:

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'backend')
python -m pytest backend/tests/test_repository.py -q
```

Ожидаемый результат: обычные гостевые маршруты удаляются после истечения заданного
retention, а `ACTIVE` и `PAUSED` не удаляются обычной очисткой и остаются доступными для
восстановления.
